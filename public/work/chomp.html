case study · three.js · live and free to play

A whole 3D game, with one person directing and an AI writing the code.

Chomp 3D: Wally's Cairns Adventure is a complete browser game: seven levels across real places in Far North Queensland, a story with an ending, a points system and leaderboards. I designed it and made every decision; an AI wrote the code under rules I set, and nothing was called done until it had been run and tested.

The problem

Everyone has seen an AI write a small demo. The open question for a team is whether a person can direct an AI through something large, with many parts that have to keep working together, and come out with software that is finished, tested and live rather than a pile of half-working pieces.

A game is a hard way to answer it. It has to look right, feel right and run on a phone, and every change can quietly break something three levels away.

Why it is hard

  • Size. About 24,100 lines of the game's own code in 116 files, 147 3D model files and 17 pages a player can open. No one keeps all of that in their head, human or AI.
  • Coupling. A save file, a points book, an outfit and a hat all have to survive moving between pages, a failed level, a return visit and a new game.
  • Feel. Tests can prove a sum. They cannot prove a camera feels right, so the human has to play it and say what is wrong, and the fixes have to land without breaking the rest.
  • Respect. It is set on the country of real peoples, and shows real places. That needs care, review and plain statements of what is and is not real.

What I did

I wrote the story, designed the levels, picked every place and character, and set the rules the AI worked under. The AI wrote the code in VS Code and ran the tests. The rules that mattered:

  • Every rule of play lives in a plain module with its own tests, apart from the drawing, so it can be checked without a browser.
  • Nothing is reported as working until it has been run. Claims are labelled as tested or not.
  • When I find a bug by playing, it is fixed and a test is written that would have caught it.
  • The AI says plainly what it did not check, and never fills a gap with a guess.

The proof

  • 1,022 unit checks in 30 suites cover the rules: the trip and its keys, scoring, return visits getting harder, the currency, hats and outfits, the leaderboard's limits, and the feedback form's defences.
  • 107 browser checks drive the real game in Chrome on desktop and phone sizes: every page loads clean, a whole level is completed and then failed, the shop sells and saves a hat, the rhythm game floats the boat on the beat and not off it, and the live site passes the same suite.
  • Bugs the tests caught before players did: a level that crashed only on phones, scores that could come out as fractions a leaderboard would refuse, a swim where holding forward pinned the player against an invisible wall, and pages that lost their place on the hosted site because it serves addresses without ".html".
  • Bugs I caught by playing, each now covered by a test: a map that, closed with its X, left the camera circling with no player in sight.

After launch: a beta, run like a product

  • Versioned releases. Fifteen beta releases so far. One script refuses to release if anything is uncommitted or any test fails, then tags the version on GitHub and publishes a labelled Cloudflare deployment that can be rolled back with one command.
  • Tester feedback, acted on. A beta testers page and a feedback form that reaches me without showing my address. The first tester found level one too hard, so the first visit now starts gentle and builds. Playing it on my own phone showed the touch controls were awkward, so they were redesigned as a diamond of buttons.
  • Every way to play. Keyboard and mouse, a game controller, touch, and VR headsets through WebXR, where the view turns in steps so it stays comfortable.
  • Installable, with a prompt to update when a new version is out.

Try it

It runs in any modern browser, on a phone or a computer, with nothing to install: playbutterflyfx.com/chomp. It is free, has no ads, and saves your game on your own device.

Technologies and skills

  • JavaScript and three.js (WebGL): seven levels, rigged and animated models, water, day and night, with no build step.
  • WebXR for VR headsets, plus keyboard and mouse, game controllers and touch controls designed from play testing.
  • Cloudflare Workers and KV: the leaderboard, and a feedback form that reaches me without showing my address.
  • Release engineering: semantic versions, a release script that refuses to ship uncommitted or failing code, GitHub tags and labelled Cloudflare deployments with one-command rollback.
  • Testing: Node.js unit suites and Puppeteer browser tests on desktop and phone sizes, run against the live site too.
  • Installable web app with update prompts, and Web Audio for sound.
  • 3D asset pipeline: AI-generated models (Meshy) reduced, rigged and animated for real-time use.
  • AI-assisted engineering with Claude Code in VS Code, under written standards.

What it does not claim

  • It is a personal portfolio piece and skills demonstration, not a commercial product.
  • The AI did not design it. The ideas, the story and the decisions are mine; the AI implemented and tested them under my direction.
  • The cultural content is going to Aboriginal and Torres Strait Islander people for review, and will change where they say it should.
  • How it runs on every phone is not yet measured across devices.
